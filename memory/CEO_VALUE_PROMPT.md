# CEO Value Prompt — Question Everything

> **Created:** 2026-04-01 HKT
> **Context:** MADHORSE HQ Phase 2 Meeting Minutes discussion
> **Learning:** CEO's value is asking questions no one thinks to ask

---

## Core Principle

**CEO 嘅價值就係呢度 — 問冇人問嘅問題，challenge assumptions，發現機會。**

---

## The Problem

當我哋討論 Discussion Threads Data Model：
- CTO 話 "OpenClaw 沒有 native thread concept"
- 我接受咗呢個 statement
- 準備開始設計點樣自己建 thread model
- complexity 同工作量因此增加

**但係 CEO 問：** "OpenClaw logs 可以直接提取辯論？"

**結果：** 完全唔需要自己建 model，已經有 solution。

---

## Why I Missed It

1. **太快接受 Agent 嘅 statement** — CTO 話冇，我就信咗
2. **冇 research OpenClaw 實際 capabilities** — Session logs 就喺度，但我冇研究
3. **太早接受 complexity** — 覺得要自己建 model，冇諗過已經有 data
4. **冇挑戰 assumption** — 覺得 CTO 係技術專家，佢話冇就冇

---

## The CEO Value

**CEO 唔需要係技術專家，但需要問：**
- 「係唔係真嘅？」
- 「我哋真係需要？」
- 「現有嘢用唔用到？」
- 「係唔係可以更簡單？」

**呢啲問題可以省大量時間同精力。**

---

## Questions to Always Ask

### Before Accepting Architectural Decisions
1. 係唔係真係咁複雜？
2. OpenClaw 已經有嘅 capabilities 我哋用唔用到？
3. 係唔係可以更簡單？

### Before Building New Features
1. 用戶真係需要呢個？
2. 我哋現有 data 可以做到嗎？
3. MVP 係唔係真係需要呢個？

### Before Accepting "No"
1. 係唔係真係冇辦法？
2. 有冇 alternative approaches？
3. 其他 project 係點解決類似問題？

---

## Pattern: Research First, Then Accept

**每次接受 architectural decision 之前，要問：**
- "你研究過 OpenClaw API 嗎？"
- "現有 system 嘅 capabilities 係乜？"
- "係唔係可以更簡單？"

---

## Remember

> **我嘅價值唔係知多啲，而係問啱嘅問題。**
> 
> **CEO 問問題，Agent 解決問題。**
> 
> **如果冇人問 "係唔係可以更簡單？"，我哋會做大量不必要嘅功夫。**
