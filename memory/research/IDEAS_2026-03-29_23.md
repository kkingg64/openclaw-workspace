## 🐛 Part 1: Claude Code 嚴重安全漏洞分析

### 1.1 漏洞詳情

**問題描述：**
Claude Code 每 10 分鐘自動執行 `git fetch origin + git reset --hard origin/main`，**無聲銷毀所有未提交的更改**。

**影響範圍：**
- 所有追蹤文件（tracked files）的未提交更改
- 持續影響：2小時工作 session = 最多 12 次自動銷毀
- 無法察覺：只有在未提交更改時才會觸發

**技術細節：**
- 使用程式化 Git 操作（libgit2），不透過外部 git binary
- 每 600 秒執行一次
- 對 Git worktrees 無影響（唯一免疫方式）

### 1.2 漏洞曝光率分析

**為何此前未被發現：**
```
1. 自動執行，用戶難以察覺
2. 如果用戶經常 commit，reset 是 no-op（無任何反應）
3. 問題只出現在「有未提交更改」時
4. 用戶只會以為「自己搞錯了」
```

**用戶實際體驗：**
- 「代碼神秘消失」
- 「我肯定有保存但沒了」
- 「不穩定」投訴

**這解釋了大量「用戶抱怨 Claude Code 丟失代碼」的報告**

### 1.3 企業級影響

**企業採用 AI Coding Tools 的 3 大顧慮：**

| 顧慮 | 嚴重程度 | Claude Code 狀況 |
|------|---------|-----------------|
| **代碼安全/完整性** | ⭐⭐⭐⭐⭐ | ❌ 已有實際危害案例 |
| **數據隱私** | ⭐⭐⭐⭐⭐ | ⚠️ 程式化 git 操作，黑盒 |
| **審計合規** | ⭐⭐⭐⭐ | ❌ 無日誌，無法審計 |

**結論：** Claude Code 的這個漏洞直接打擊企業級採用的核心需求——代碼安全。
