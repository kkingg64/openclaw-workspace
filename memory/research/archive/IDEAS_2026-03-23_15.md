### 平台化策略嘅關鍵成功因素

```
【點解 WordPress.com 能成功而其他失敗？】

因素 1: 市場份額

因素 2: MCP 標準支持
- 採用通用協議，降低用戶學習成本

- 所有操作需要人類批准
- 保留「最終控制權」減少企業疑慮

因素 4: 生態系統思維
-唔係要取代人類，而係增強人類能力
- 讓內容創作者用 AI 加速工作，而非失業
```

## 4️⃣ AI Agent 落地失敗案例與教訓

### 2026 Q1 常見失敗模式

```
【AI Agent 落地失敗矩陣】

失敗模式 1: 期望管理不當
─────────────────────────
問題：管理層以為 AI Agent = 無限 worker
現實：需要大量 setup、prompt 工程、監控
教訓：設定清晰的 MVP 範圍

失敗模式 2: 數據準備不足
─────────────────────────
問題：數據質量差 / 分散 / 無 API
現實：AI Agent 係「垃圾 in，垃圾 out」
教訓：先做數據整理，再上 AI Agent

失敗模式 3: 缺乏人類監督
─────────────────────────
問題：完全放手，導致錯誤累積
現實：AI Agent 需要 human-in-the-loop
教訓：審批機制係必要嘅

失敗模式 4: 成本計算錯誤
─────────────────────────
問題：忽略 LLM 調用成本 × 使用量
現實：大量使用時成本會爆炸
教訓：用畢計算機模擬真實使用量成本

失敗模式 5: 整合挑戰
─────────────────────────
問題：舊系統沒有 API，無法對接
現實：企業 IT 環境複雜
教訓：選擇 SaaS 優先，舊系統其次
```

### 成功落地框架

```
【AI Agent 落地成功框架 — 3-6-3 模型】

3 個準備階段：
├── 1. 流程文檔化（人類專家寫出決策邏輯）
├── 2. 數據清理（結構化、標籤化、可訪問）
└── 3. Pilot 選擇（選擇高價值、低風險場景）

6 個實施步驟：
├── 1. 定義成功標準（可量化）
├── 2. 選擇合適框架（MCP/LangGraph/AutoGen）
├── 3. 構建 MVP（最小可行產品）
├── 4. 人類審批流程（所有操作需要批准）
├── 5. 監控和迭代（每週回顧）
└── 6. 擴展成功案例（從 1 個流程到 10 個）

3 個關鍵原則：
├── 透明（團隊知道邊個係 AI，邊個係人類）
├── 可逆（所有 AI 操作可以 undo）
└── 可解釋（AI 決策邏輯可以解釋）
```

```
- 先進機器人
- Edge AI 芯片

【為何重要】

├── 實時處理（不能等待雲端響應）
```
