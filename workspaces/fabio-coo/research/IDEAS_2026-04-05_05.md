```
┌─────────────────────────────────────────────────────────────┐
│        CODING AGENT 六個核心組件 — 2026                     │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. Live Repo Context (WorkspaceContext)                    │
│  ├─ 知道喺咩 Git repo、branch、project structure            │
│  ├─ 建立 "stable facts" workspace summary                  │
│  ├─ 知道邊個 test command、邊個文件包含 instructions        │
│  └─ 避免每個 prompt 都從零開始                              │
│                                                             │
│  2. Prompt Shape And Cache Reuse                            │
│  ├─ Stable prompt prefix = general instructions + tools     │
│  ├─ Session state = recent transcript + user request       │
│  ├─ 唔需要每turn重新build整個prompt                         │
│  └─ 智能runtime重用不變嘅部分                               │
│                                                             │
│  3. Structured Tools, Validation, And Permissions          │
│  ├─ 預先定義嘅allowed tools + clear inputs                  │
│  ├─ Tool call flow:                                         │
│  │   Model emits action → Harness validates                │
│  │   → Optional approval → Execute → Bounded result       │
│  ├─ 防止model執行任意command                                │
│  └─ Path validation (唔准走出workspace)                   │
│                                                             │
│  4. Context Reduction And Output Management                │
│  ├─ 點樣有效地reduce context when it grows                  │
│  ├─ 管理長 session 嘅輸出                                    │
│  └─ 避免 context overflow                                   │
│                                                             │
│  5. Transcripts, Memory, And Resumption                    │
│  ├─ SessionStore用於記錄每個interaction                     │
│  ├─ 可以resume之前嘅session                                 │
│  ├─ 長期記憶 vs 短期                                        │
│  └─ 呢個係Claude Code區別其他工具嘅關鍵                     │
│                                                             │
│  6. Delegation And Bounded Subagents                       │
│  ├─ 可以delegate任務俾subagent                               │
│  ├─ Subagent喺隔離環境運行                                  │
│  └─ 類似OpenClaw嘅sessions_spawn                             │
└─────────────────────────────────────────────────────────────┘
```

### 2. 💎 AI Agents 失敗嘅真正原因 — 40年前嘅解決方案

**Source:** Cyrus Radfar (Hacker News thread) — "AI agents keep failing. The fix is 40 years old"

呢個係今日最有價值嘅發現。Gartner預測2027年底前40%+嘅agentic AI項目會被取消，MIT報告95% AI pilot失敗。但問題唔喺模型，係architecture。

**失敗數據：**
```
AI AGENT FAILURE STATS (2026)
──────────────────────────────
• Gartner: 40%+ agentic AI projects cancelled by end of 2027
• MIT: 95% of generative AI pilots failing to deliver ROI
• Most agent projects never make it to production
• Ones that do often get rolled back within a year

THE PROBLEM IS ARCHITECTURAL, NOT MODEL QUALITY
```

**點解失敗？**
```
典型失敗模式：
Agent reads function that takes a list, returns a list
Agent writes tests, they pass
Function fails in production because:
 - depends on global config
 - depends on database singleton
 - signature never declared these dependencies
 - Agent had NO WAY to know

每個iteration引入 subtle state corruption
呢啲問題 compounding → 最終系統崩潰
```

**解決方案：Functional Programming + SUPER原則**

```
┌─────────────────────────────────────────────────────────────┐
│              SUPER — AGENT-FRIENDLY CODE原則               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  S — Side Effects at the Edge                              │
│  ├─ I/O、database、API calls 只喺外層                        │
│  ├─ 核心邏輯係 deterministic                                 │
│  ├─ Agent 可以rewrite core logic唔擔心觸發payment           │
│                                                             │
│  U — Uncoupled Logic                                        │
│  ├─ Dependencies passed in, not pulled from globals        │
│  ├─ Agent可以swap implementations for testing              │
│  └─ 唔需要mock Redis/connection strings/Docker              │
│                                                             │
│  P — Pure & Total Functions                                │
│  ├─ Same input → Same output, 永遠咁                         │
│  ├─ Handle every input (包括error cases)                    │
│  ├─ Agent可以read return type知道邊個case會fail              │
│                                                             │
│  E — Explicit Data Flow                                    │
│  ├─ 數據綫性地從input流到output                              │
│  ├─ 冇action-at-a-distance                                  │
│  └─ Agent可以跟蹤每個step做咩                                │
│                                                             │
│  R — Replaceable by Value                                  │
│  ├─ 可以swap function call with computed result            │
│  ├─ Agent可以cache、skip、reorder computation               │
│  └─ 代數級別嘅代碼reasoning                                  │
└─────────────────────────────────────────────────────────────┘
```

**SUPER vs Traditional 對比：**
```
Before (HOSTILE TO AGENT):
────────────────────────────────────────
def evaluate_options(items, threshold):
    config = load_config()      # hidden dependency
    db = get_database()        # hidden singleton
    log("evaluating")          # side effect
    results = []
    for item in items:
        if item.value > config.threshold:  # invisible
            db.save(item)       # triggers real write
            results.append(item)
    return results

After (AGENT-FRIENDLY):
────────────────────────────────────────
def evaluate_options(items, threshold, config, db, logger):
    # ALL dependencies explicit in signature
    results = []
    for item in items:
        if item.value > threshold:
            results.append(item)
    return results
    # Caller handles: config, db, logging
```

**為何呢個係大機會：**
- 大量現有codebase不符合SUPER原則
- 需要工具去分析 + 重構
- 需要培訓開法者呢個新範式
