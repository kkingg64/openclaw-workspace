### ⚠️ 重要：數據獲取策略

由於 Vercel 係 public cloud，唔可以直接訪問 Internal VPS既 Docker API。我地有兩個方案：

| 方案 | 描述 | 優點 | 缺點 |
|------|------|------|------|
| **方案 A (推薦)** | Bridge Service + API Proxy | 安全、易debug | 需要多一個 service |
| **方案 B** | 開放特定 Port (風險高) | 簡單直接 | 安全風險大 |

**CTO 建議：方案 A - Bridge Service**

1. **VPS 上既 Bridge Service** (細型 Go/Python microservice)
   - 监听 internal requests
   - 封裝 Docker API / Prometheus queries
   - 僅 expose 必要既 endpoints

2. **Vercel 上既 API Routes**
   - 作為 proxy，轉發 request 去 Bridge Service
   - 可加入簡單既 cache (Vercel KV 或 memory)

## 3. 數據源設計

### 🔍 數據獲取矩陣

| 數據類型 | 來源 | 獲取方式 | 頻率 |
|----------|------|----------|------|
| **系統健康** | Docker API | `GET /containers/json` | 30秒 |
| **容器資源** | Docker Stats API | `GET /containers/{id}/stats` | 30秒 |
| **項目狀態** | Git / File System | 讀取專案狀態 | 5分鐘 |
| **商業指標** | Mock Data / API | 預設範本 + 動態 | 1分鐘 |
| **歷史數據** | Prometheus | `GET /api/v1/query_range` | 1分鐘 |

### 🐳 Docker API 整合

```typescript
// lib/docker.ts
export async function getContainerStats() {
  const response = await fetch('http://bridge-service:8080/api/docker/stats');
  return response.json();
}
```

### 📊 Prometheus 整合 (Optional)

如需要更精細既 metrics：
- 安裝 `node_exporter` 在每個容器
- 使用 `prometheus-api-client` 查詢數據

- [ ] **CORS**: 限制僅 Vercel domain 可訪問
- [ ] **Rate Limiting**: API routes 需加 limit
- [ ] **.env**: 永遠唔好 commit
