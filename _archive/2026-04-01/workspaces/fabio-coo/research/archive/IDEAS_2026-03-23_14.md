## 1️⃣ AI Agent 安全風險全景圖（2026 Q2）

### 點解 AI Agent 比傳統軟件更危險？

```
【AI Agent 的獨特風險維度】

傳統軟件：
- 輸入 → 確定性輸出
- 行為可預測、可測試
- 漏洞可修補、版本可控

AI Agent：
- 自然語言指令 → 自主決策執行
- 行為隨輸入、環境變化
- 可以穿越系統邊界操作
- 錯誤後果放大（自主執行而非建議）
```

### AI Agent 安全漏洞的獨特性質

```
【挑戰 #1：指令注入 (Prompt Injection)】

攻擊方式：
- 在輸入中隱藏恶意指令
- AI Agent 被誘導偏離原本任務
- 典型案例：將恶意指令藏在網頁內容、郵件、文件評論中

防護難度：
- 傳統安全工具無法檢測（因為係 "正常輸入"）
- 沒有明確的惡意軟件特徵
- 防護需要理解語義和上下文

────────────────────────────
【挑戰 #2：代理遺留 (Agentic Loop)】

問題描述：
- AI Agent 互相調用，形成複雜調用鏈
- 當錯誤發生時，問題根源難以追踪
- 責任邊界模糊（「邊個嚟孭？」）

防護難度：
- 需要完整的調用追蹤
- 跨系統審計能力
- 多數現有工具不支援

────────────────────────────
【挑戰 #3：權限蠕升 (Privilege Escalation)】

問題描述：
- AI Agent 獲得某些初始權限
- 通過逐步操作擴大權限範圍
- 最終獲得超出原設計的訪問能力

防護難度：
- AI 行為具有適應性
- 傳統的權限模型不適用
- 需要持續監控而非一次性審計

────────────────────────────
【挑戰 #4：數據過度訪問 (Excessive Data Access)】

問題描述：
- AI Agent 任務範圍內的數據訪問
- 但實際只需要極小部分數據
- 導致數據洩漏風險放大

防護難度：
- 任務定義模糊時，數據訪問範圍難以界定
- 多數 AI Agent 框架默認 "full access"
- 需要新的數據訪問控制模型
```
