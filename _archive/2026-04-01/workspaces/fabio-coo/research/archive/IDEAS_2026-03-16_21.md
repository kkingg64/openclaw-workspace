## 📈 研究主題: AI Agent Infrastructure - MCP Alternatives + Hardware

### 1. 🔥 MCP Context Bloat 危機 (2026-03 最新)

**問題核心:**
- 每個 MCP tool 消耗 **550-1,400 tokens** (name, description, JSON schema, field descriptions, enums, system instructions)
- 3 個 MCP servers 可以消耗 **143,000 / 200,000 tokens** = **72% context window**
- 只剩低 57,000 tokens 俾 conversation, documents, reasoning, response

**數據證明 (Scalekit benchmark):**
- 75 head-to-head comparisons (same model: Claude Sonnet 4)
- **MCP 4-32× more tokens** than CLI for identical operations
- Simplest task (checking repo language):
  - CLI: **1,365 tokens**
  - MCP: **44,026 tokens**

### 2. 🛠️ 三種解決方案對比

| Approach | Tokens | Pros | Cons |
|----------|--------|------|------|
| **MCP + Compression** | High | Structured, typed schemas | 需要 middleware, tool registry |
| **Code Execution (Duet)** | Medium | 可處理複雜 workflow | Security risk, sandboxing 成本 |
| **CLI (Apideck)** | **~80 tokens** | Progressive disclosure, 低成本 | 不夠靈活 |

### 3. 🔧 Apideck CLI - The Alternative

**核心概念:**
- 唔將 schemas 放入 context window
- 給 agent 一個 CLI，等佢自己 explore
- Progressive disclosure: `tool --help` → `tool subcommand --help`

**Prompt example (~80 tokens):**
```
Use `apideck` to interact with the Apideck Unified API.
Available APIs: `apideck --list`
List resources: `apideck <api> --list`
Operation help: `apideck <api> <resource> <verb> --help`
```

**商業價值:**
- 大幅降低 context cost
- 適合多 API 整合既 agent
- 但 limited flexibility for complex workflows
