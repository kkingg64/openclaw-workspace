## 🎯 為何選擇 AI Verification 領域？

根據最新 Hacker News 趨勢，我注意到一個重要訊號：

> **"Agents that run while I sleep"** - 成為 developer community 熱門话题

越來越多工程師用 AI Agent 自動寫 CODE，但核心痛點係：**點樣知 AI 寫既 CODE 係啱既？**

---

## 📈 市場趨勢分析

### 1. AI Coding 爆發但驗證落後

**關鍵數據 (from Claude Code Workshop):**
- 100+ 工程師受訪使用 AI 寫 CODE
- Teams 用 AI 後合併 40-50 PRs/week (之前得 10 PRs)
- **但冇可靠既驗證方法** — 最常見投訴

### 2. 現有方案既問題

| 方案 | 問題 |
|------|------|
| AI 寫 Test + AI 寫 Code | Self-congratulation machine - 自己檢查自己 |
| Human Code Review | 睇唔切咁多 AI 生成既 CODE |
| Hire more reviewers | Hire 唔切，成本太高 |
| Same AI for both | 犯同一樣既錯誤，睇唔到既野一樣睇唔到 |

### 3. 新興解決方案：TDD + AI

**核心諗法:** 
1. **Write test first** — 用 English 寫 acceptance criteria
2. **AI builds to spec** — Agent 跟住 spec 寫 CODE
3. **Something else verifies** — 其他 Agent/工具驗證

**成功案例: opslane/verify**
- Claude Code Verification Layer
- 4 stages: Spec Interpreter → Planner → Agents (per AC) → Judge → Report
- 用 Playwright browser agents 做 automated testing
- 輸出 pass/fail + screenshots + session recordings

---

## 🛠️ 技術架構分析

### opslane/verify Architecture

```
[Spec Doc] → [Spec Interpreter] → [Planner]
                              ↓
        ┌─────────────────────┼─────────────────────┐
        ↓                     ↓                     ↓
  [Agent: AC 1]        [Agent: AC 2]        [Agent: AC n]
        ↓                     ↓                     ↓
        └─────────────────────┼─────────────────────┘
                              ↓
                          [Judge]
                              ↓
                          [Report]
```

### Key Features

| Stage | 功能 |
|-------|------|
| Pre-flight | Bash checks: dev server running? auth valid? |
| Planner | Opus call: 讀 spec + changed files，計劃點測試 |
| Browser Agents | Sonnet call per AC，並行執行 |
| Judge | 睇 screenshot + traces，斷 pass/fail |
| Report | 輸出結果，failures 有 screenshot + video |

### Tech Stack

- Claude Code (headless mode: claude -p)
- Playwright MCP
- No custom backend needed
- No extra API keys (用現有 Claude OAuth token)
